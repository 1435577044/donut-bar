Sileo 装不上 —— 真正的原因与修好的包

报错 Encountered a section with no Package: header / Problem with MergeList · 2026-09-21

先认错  我上一次说是"文件名里的下划线被百分号编码"造成的 —— 这个判断是错的。

你把文件名改成 badgebar-stage.deb（没有下划线）之后，报错一模一样。这就推翻了我的假设。教训是：同一个症状再次出现时，应该推翻原假设，而不是在原来的解释上继续加猜测。

真正的原因  我们的 control.tar.gz 缺少第一个 . 目录条目 —— 而全部 8 个参照包都有。这是唯一一处与官方包不一致的地方，已经修好，新包在下面。

一、证据：唯一的差异在这里

我这次专门对比了所有参照包的 control.tar 成员列表：

包control.tar 成员
我们的（手工拼的 ar）['./control']  缺 `.`
原始有根包 BadgeBar X-1.3.7.deb['.', './control']
官方 oldabi['.', './control']
官方 ellekit['.', './control', './postinst', './postrm', './preinst']
官方 ws.hbang.alderis['.', './control']
官方 ccsupport['.', './control']
官方 preferenceloader['.', './control']
官方 rootless-compat['.', './control']

8 个参照包无一例外都有首个 . 目录条目，只有我们手工拼的那个没有。 dpkg 对这个差异不在意（所以 v5 能装上），但 APT / Sileo 读 deb 的代码路径更严格。

二、报错在说什么

E: Encountered a section with no Package: header
E: Problem with MergeList /…/var/tmp/badgebar-stage.deb
E: The package lists or status file could not be parsed or opened.

MergeList 是 APT 解析「包列表」用的函数。也就是说：APT 在把我们的 .deb 当成一个 Packages 索引去读，读到 ar 头部发现里面没有 Package: 字段，于是报"没有 Package 头"。

换句话说：Sileo 的「从文件安装」把这个 deb 注册成了一条"源/列表"，而不是交给 dpkg 安装。 这也解释了为什么它跟文件名无关——每次都是同样的路径。

三、我已经做的修改

项目改动
control.tar 成员改成 ['.', './control']，与 8 个参照包完全一致
./control 内容一字未改（已用 sha256 校验前后一致）
data.tar.gz逐字节未变（即二进制、签名、依赖都没动）
其余容器字段ar 头、成员名、size/mtime/mode 字段、magic、2 字节对齐、debian-binary=2.0\n、成员顺序 —— 本就与官方一致
审计audit FAIL 0（含签名、ABI、依赖检查）

四、按这个顺序做

第 0 步 · 先把 APT 的坏状态清掉（必做）

之前几次失败可能已经在 APT 里留下了一条指向本地 .deb 的坏记录，不清掉的话每次刷新都会报这个错。

  1. Sileo → 底部「软件源」→ 点右上角「编辑」→ 逐条看，找到路径里带 var/tmp、jbroot 或以 .deb 结尾的条目，删掉它。
  2. 然后下拉刷新。
  3. 如果刷新还报同样的错：这只是缓存脏了，不影响后面的安装——跳过它继续下一步即可。
第 1 步 · 用修好的新包再试一次

下面这两个包已经修好了 control.tar 布局，文件名也没有下划线：

badgebar-stage.deb   ← 安全自检版（先装这个）
badgebar-final.deb   ← 正式版（自检通过后再装）

sha256：stage 084ec406f5ff9388… ／ final 46612a5342205b84… （如果 Filza 显示的字节数不是 171,324 / 171,030，说明传输中被截断了，重新传一次）

第 2 步 · 如果 Sileo 仍然报错，改用 Filza 安装

Filza 走的是 dpkg，不经过 Sileo 的源/列表机制，也就绕开了这个问题的根源：

把 badgebar-stage.deb 放进手机 → 在 Filza 里找到它 → 长按 → 安装。

第 3 步 · 或者用命令行（最可靠） 
dpkg -i /var/mobile/Documents/badgebar-stage.deb
# 若提示依赖未满足：
apt-get -f install

NewTerm / MTerminal 都行；有 SSH 的话 ssh root@设备IP（默认密码 alpine）。

第 4 步 · 换 Zebra 试试

先在 Sileo 里从源装上 Zebra（走源安装是正常的），再用 Zebra 的本地 deb 安装功能装我们的包。它的本地安装实现和 Sileo 不同。

五、完整顺序（别忘 oldabi）

  1. 先装 oldabi（Name: Legacy arm64e Support，2.0.1+roothide-1；别装带 -stub 的）→ 注销
  2. 装 badgebar-stage.deb → 注销
  3. 反复进出「设置」，并打开 BadgeBar X 面板：一切正常 → 卸载自检版；设置崩了 → 系统不受影响，把崩溃日志给我
  4. 装 badgebar-final.deb → 注销 → 看主屏角标

麻烦你回一句：这一次是第 1 步就成功了，还是仍然报同样的错？

如果修好 control 布局后仍然报错，那就说明 Sileo 这条"从文件安装"的路在你这台机器上确实是坏的，我们直接走 Filza / 命令行 / Zebra，不再和 Sileo 纠缠。
