1. 改动一：横条上下偏移默认回到 80

这是一次精确回退 —— 之前（内部版本 4.0.1）把默认值从 80 改成 78 时同步改了三个地方， 本次逐一改回，不多不少：

位置4.0.61.0.0作用
dylib DEFAULTS[1]7880 加载期写入的默认 Y
Root.plist 的 Y 滑块[38,118] 默认 78[40,120] 默认 80 面板上的把手位置（保持「默认值 = 范围正中」）
DEAD_STR 默认值载体键'78''80' 「恢复默认设置」按钮写回的值

为什么改默认值不会连带移动标定基准

这是本次唯一需要判断的地方。glue 的实际定位公式是：

center_y = ringC_y + (Y − KEY_Y)        KEY_Y = 5（标定量，未动）

而构建脚本里另有 Y_CTR = DEFAULTS[1] 与 DY_INT = Y_CTR − KEY_Y。 把两式合起来看：

DY_INT + (Y − Y_CTR) = (Y_CTR − KEY_Y) + Y − Y_CTR = Y − KEY_Y

Y_CTR 完全抵消，而且已 grep 确认 DX_INT/DY_INT 在本脚本内未参与任何代码生成（仅用于注释）。因此改 DEFAULTS[1] 只改变「默认位置的数值」，不会动标定基准 —— 默认位置比 4.0.1~4.0.6 下移 2pt，回到 4.0.0 标定的位置。

已在脚本里加了防漂移断言：构建时强制校验 2 × 默认值 == 最小值 + 最大值（默认值必须落在范围正中）与 滑块默认值 == DEFAULTS[i]（三处同步）。任一处漏改会直接构建失败，不会静默出错。

2. 改动二：版本号 1.0.0

版本号只有一个来源（脚本 VERSION 常量），它同时决定 control 的 Version: 与插件设置页顶部横幅的版本槽。 '1.0.0' 与 '4.0.6' 同为 5 字符，因此原地改写即可， 不需要动用为 ≥6 字符准备的指针重定向方案。

关键项是「从二进制里读回来」而不是复述构建日志

改默认值这类改动最容易出的错是「日志显示改了、实际没生效」。因此专项验证直接反汇编产出二进制：

  • prefs_to_rect 的 4 个默认值立即数 = [40, 80, 30, 6]（两切片）
  • 「恢复默认」按钮实际引用的 CFString = ['40','80','30','6']， 并与配对的键 ['pfDonutDot','#EB4D3DFF','#','#FFFFFF'] 一一对应 （解析 adrp+add 指令对 → 查 __cfstring 表得到）
  • 版本槽内容 = '1.0.0'，且原始串 v2.0.3 已无残留
  • 标定常量 KEY_X=76 / KEY_Y=5 各只出现 1 处（未被牵连）

最小差异（4.0.6 → 1.0.0）：每一处都能归因

文件差异性质
Donut.dylib 每切片 3 处：0x7c70 的 2 字节（mov x0,#78→#80） + 20 B + 32 B 签名页哈希预期
DonutPrefs 每切片 5 处：__cstring 里 '78'→'80'、 '4.0.6'→'1.0.0'（1+1 字节，中间的 .0. 相同） + 20 B + 32 B 签名页哈希预期
Root.plist1296 → 1288 B（Y 滑块的 min/max/default） 预期
control仅 Version: 行预期
3 个图标 PNG逐字节相同未动体积优化

那 20 B / 32 B 是 签名被正确重算的证据（改动的字节落在代码页内，两个 CodeDirectory 各自的页摘要都要更新，长度恰好等于该算法的 hashSize）。若差异出现在签名区之外又解释不清，就不该交付。
