为什么不会崩溃

插件所有拦截都通过运行时的 objc_getClass() 动态取类，而不是编译期硬绑定。系统里找不到某个类或方法时，拦截会被安全跳过，只是对应功能不生效——不会导致 SpringBoard 崩溃或安全模式。这是这个插件设计上比较稳妥的一点。

四、唯一的实质风险：iOS 17 换了角标定位方式

iOS 17.0 的 SBIconAccessoryView 协议里出现了一个新的必需方法：

@protocol SBIconAccessoryView <SBReusableView, UIPointerInteractionDelegate>

// ——— 以下 5 个方法位于 @required 块（协议必需，iOS 17 必然实现）———
- (void)setAccessoryBrightness:(double)arg1;
- (_Bool)displayingAccessory;
- (struct CGPoint)accessoryCenterForIconBounds:(struct CGRect)arg1;   // ← iOS 17 新增，决定角标位置
- (void)configureForIcon:(SBIcon *)arg1 infoProvider:(id)arg2;        // ← 本插件已 hook
- (void)configureAnimatedForIcon:(...)infoProvider:(...)animator:(...)arg3;

@optional
@property(retain, nonatomic) UITapGestureRecognizer *actionTapGestureRecognizer;
@property(retain, nonatomic) id <SBIconListLayout> listLayout;
@property(retain, nonatomic) SBFParallaxSettings *parallaxSettings;
- (void)setLegibilityStyle:(long long)arg1;
@end
两条关键事实（同一份 iOS 17.0 官方头文件直接给出）
  • configureForIcon:infoProvider: 位于 @required 块 → iOS 17 必然实现，本插件的核心 Hook 一定命中。
  • accessoryCenterForIconBounds: 同样位于 @required 块 → 它不只是「新增」，而是 iOS 17 用来决定角标中心点的必需接口。而本插件没有 hook 它。

含义是：iOS 17 里「角标放在哪」改由系统调用 accessoryCenterForIconBounds: 决定（同类插件 dotto++ 为此专门加了 iOS 17 专用定位 hook，并移除了失效的 _frameForAccessoryView:）。

而 BadgeBar 是 iOS 13 时代的定位逻辑：它在 SBIconBadgeView.layoutSubviews 里自己改写自己的 frame 来把角标摆到图标底部并拉成长条形。它没有 hook 上面那个新接口。

可能的表现说明可能性
完全正常因为 layoutSubviews 是子视图最后的布局时机，BadgeBar 在那里写入的 frame 能保留下来较高
条形位置/尺寸偏移系统在 BadgeBar 写入之后又按新规则摆正角标，把自定义位置覆盖掉；表现为条形偏离图标底部、大小不对中等
条形被裁剪或显示不全角标容器尺寸不足以容纳拉长的条形较低
应对：先实测，再用内置设置补偿

插件自身提供了位置与尺寸微调项，位置略有偏差时可原地修好，无需改包：

  • xOffsetBadge / yOffsetBadge — 角标 X / Y 偏移
  • badgeWidth / badgeHeight — 条形宽高
  • badgeRadius — 圆角半径

本报告的边界

以上全部为离线静态检测：包结构、加载命令、指针引用、签名哈希、selector 存在性、依赖可获得性均已程序化核实。但角标的实际渲染与定位属于运行时行为，必须在真机上验证——这也是第四节列出的唯一未决项。
